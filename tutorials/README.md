## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) generated from two synthetic prefixed inputs and reported a `not-measurable` verdict because the repository shipped no metric and the sample had no references. This notebook keeps that inference contract as Section 5 and adds the adaptation contract around it: a real referenced corpus under a prefix the checkpoint has never seen, three ROUGE metrics in the carried `metrics.py`, a Lead baseline and the frozen model's nearest trained prefix as reference points, a bounded fine-tuning that teaches the prefix, and an artifact that reloads. `evaluation_report` now scores supplied references for one item (`sample-sanity`) and still returns `not-measurable` without them; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 7-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry; `T5BaseText2TextPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`); no cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors` or `urllib`.
- **Data (DAT1–DAT9, ST6):** the default sample is three pinned objects — `train.jsonl` / `dev.jsonl` / `test.jsonl` of SciTLDR-A (3,155,015 / 1,124,865 / 1,204,107 bytes; SHA-256 `b222771d…` / `3191fa98…` / `fb42dd6c…`) from `raw.githubusercontent.com` at the pinned `allenai/scitldr` commit — each refused on any mismatch before it is parsed, paired abstract → title, filtered to abstracts of 200..1,600 characters with a title and de-duplicated on both sides, and drawn by a seeded shuffle into 300 / 50 / 100 records from the release's own paper-disjoint members (`check_split_disjoint` asserts it). The template adds a second *External access* bullet naming the host, the byte counts and the Apache-2.0 licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.generate` with sanity checks on trained prefixes plus the new-prefix probe (inference contract) → `lead_baseline` + `pipe.evaluate` on the frozen model under the new prefix and under `summarize: ` (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.generate` on unseen abstracts + `pipe.evaluate` + `evaluation_report` + the trained-prefix re-check (inference) → `pipe.save_artifact` → `T5BaseText2TextPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the pipeline emits no probability, confidence or score; ROUGE-1/2/L are corpus-level n-gram agreement with references (own implementations, best over the references, rouge-score-style, not rouge-score-identical, no stemming, no faithfulness); no acceptance threshold ships, and `stopped_by == 'max_new_tokens'` is explained as a cut output. Four unseen abstracts are scored with a `measured-small-sample` verdict that names the missing dispersion.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the Lead-1 baseline, the frozen model under the new prefix and the frozen model under `summarize: ` are scored on the same 100 test abstracts as the adapted model with the same generation settings, `mean_output_words` and `mean_reference_words` are printed beside every score, and every metric is labelled as one seeded split of one corpus with no dispersion estimate; the notebook states that the adapter changes the shared decoder blocks and re-checks one trained-prefix input after adaptation.
- **Split integrity (SPL1–SPL8):** the split is seeded and source-disjoint (the release's own train/dev/test partition); validation selects the epoch and the test split is used for nothing but the final evaluation; the notebook states that pairs from one document collection or author must be split by that grouping.
- **Ceilings (VAL6):** `MAX_TEXT_CHARS` (20,000), `MAX_INPUT_TOKENS` (512, rejected not truncated), `MAX_NEW_TOKENS` (512), `MAX_NUM_BEAMS` (8), `MAX_PREFIX_CHARS` (64), the record bounds (8..20,000), the reference ceiling (400 characters), the id pattern and the training-only 512/64-token truncation are stated in the Prerequisites and printed before the model runs; four dataset refusals and one settings refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user pairs and the caller's `PREFIX` flow through the same validation, seeded source-disjoint split, baselines, fine-tuning, evaluation, inference, export and reload cells. The expected schema and the privacy guidance — an internal document set with its reference outputs is restricted data — are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/t5_base_text2text_train.csv` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
